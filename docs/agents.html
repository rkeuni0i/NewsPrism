NewsPrism 에이전트 구성

같은 사건을 다룬 여러 언론사 기사를 모아 공통 사실과 주요 쟁점을 정리하는 LangGraph 파이프라인입니다. 총 14개 노드 중 9개가 LLM을 호출합니다. (기사별 "주제 판정"과 "기사별 분석"은 process_article 노드 안에서 동시에 실행됩니다.) 같은 사건 기사가 2건 이상이면 비교 경로, 정확히 1건(단독 보도)이면 팩트체크 경로로 갈라집니다.

전체 흐름

1. 기사 수집collect_articles
↓기사 10건 + 기준 사건
2. 주제 판정 × 기사 수judge_topic · 병렬
↓판정 결과
3. 기사 거르기filter_articles
↓같은 주제 기사가 2건 이상이면 계속, 아니면 종료
4. 기사별 분석 × 기사 수analyze_article · 병렬
↓기사별 분석
5. 비교compare_articles
↓공통 사실 · 주요 쟁점
검증에 통과하지 못하면 다시 쓰기 (최대 2회)
6. 중립 요약write_summary
7. 팩트·편향 검증check_bias · 2개 동시 실행
↓통과 또는 재작성 한도 도달
8. 리포트 조립build_report
LLM 호출일반 코드여러 개를 동시에 실행

기사가 이미 주어진 경우(샘플 실행)에는 1번을 건너뛰고 2번부터 시작합니다. 같은 주제 기사가 2건 이상이면 4~8번으로, 1건이고 본문이 있으면 단독 보도 경로(9~13번)로 갑니다. 그 외에는 no_report가 "비교할 수 없다"는 안내만 만들고 끝납니다.

에이전트별 역할

1

기사 수집

collect_articlesLLM 1회

키워드로 기사를 모으고, 이번 비교의 기준이 될 "하나의 사건"을 정한다.

입력
검색 키워드
하는 일
  • 주요 사건 카드가 묶어 준 기사와 검색 결과를 모은 뒤, 언론사를 중요도 순으로 최대 12곳 고른다. (카드의 언론사, 제목이 사건과 비슷한 기사, 주요 언론사 순. KBS와 KBS 뉴스는 같은 곳으로 본다)
  • 원문 주소를 찾아 본문을 추출한다. 본문을 못 얻으면 제목과 요약만 쓰고 그렇게 표시한다.
  • LLM이 기사 제목들을 보고 가장 많이 다뤄진 사건 하나를 한두 문장으로 정리한다. 이것이 기준 사건(anchor)이다.
출력
기사 목록, 기준 사건
안전장치
수집한 기사는 캐시에 저장해 다시 수집하지 않는다.
2

주제 판정

judge_topicLLM · 기사당 1회병렬

후보 기사가 기준 사건과 같은 사건을 다루는지 기사마다 판정한다.

입력
기사 1건, 기준 사건
하는 일
같은 분야라도 다른 사건·다른 시점이면 "아니오", 같은 사건을 다른 관점으로 다루면 "예"로 판정하고 근거를 한 문장 남긴다.
출력
같은 주제 여부, 판정 근거
3

기사 거르기

filter_articles코드

판정을 통과한 기사만 남기고, 비교가 가능한지 결정한다.

하는 일
같은 주제 기사만 추린다. 2건 미만이면 분석을 중단하고 no_report로 보낸다. 제외된 기사와 사유는 화면에 따로 보여준다.
출력
비교 대상 기사 목록
4

기사별 분석

analyze_articleLLM · 기사당 1회병렬

기사 한 건이 무엇을 핵심 주장으로 삼고 무엇을 강조했는지 구조화한다.

입력
기사 1건
하는 일
핵심 주장, 강조한 사실과 본문 근거 문장, 인용한 출처, 어조, 빠진 맥락을 뽑는다. 본문에 있는 내용만 쓰도록 지시한다.
출력
기사별 분석 결과
안전장치
  • 근거 문장이 본문에 글자 그대로 없으면 버린다. (환각 방지)
  • 본문 없이 제목·요약만 있는 기사는 "빠뜨린 맥락"을 주장하지 못하게 비운다.
5

비교

compare_articlesLLM 1회

기사별 분석을 모아 공통 사실과 주요 쟁점을 가려낸다.

입력
모든 기사의 분석 결과
하는 일
  • 공통 사실: 여러 언론사가 함께 보도한 사실과 보도한 언론사 목록
  • 주요 쟁점: 당사자들의 입장이 갈리는 논점. "누가 무엇을 주장하는지"와 전한 언론사를 적는다.
  • 표현·강조 차이(보조), 일부만 다룬 사실, 함께 생각할 질문
출력
비교 결과
안전장치
과반수 미만이 보도한 사실은 코드로 "공통"에서 내리고 "일부만 다룬 사실"로 옮긴다. (과대 일반화 방지)
6

중립 요약

write_summaryLLM 1회+

비교 결과를 5문장 이내의 중립적인 요약으로 쓴다.

입력
비교 결과, 이전 검증에서 지적된 문제(다시 쓸 때만)
중립 규칙
  • 사실: 과반이 보도한 내용만 단정해서 쓴다. 소수만 다룬 내용은 "○○는 ~라고 보도"처럼 출처를 붙인다.
  • 쟁점: 주체와 언론사를 함께 적고 누가 옳은지 판단하지 않는다.
  • 표현: 평가·감정 어휘(강행, 졸속, 논란 등)를 쓰지 않는다.
출력
요약문, 재작성 횟수
7

팩트·편향 검증

check_biasLLM 2회동시 실행

요약이 기사에 근거하는지, 한쪽으로 치우치지 않았는지 두 방향으로 검사한다.

검사 1
근거 검증: 요약을 사실 주장 단위로 쪼개 수집한 기사에만 근거해 "뒷받침됨 / 근거 없음 / 충돌"로 판정한다. (논문 SAFE 방식의 변형)
검사 2
편향 채점: 평가·감정 표현 여부, 출처 병기 여부, 한쪽 입장 편중 여부를 채점한다.
출력
통과 여부, 항목별 결과, 문제 목록, 주장별 판정
안전장치
  • LLM이 제시한 근거 문장이 실제 본문에 없으면 "뒷받침됨"을 인정하지 않는다.
  • 소수만 보도한 내용을 단정형으로 쓰면 코드로 문제 처리한다.
  • 통과하지 못하면 6번으로 돌아가 다시 쓴다. 재작성은 최대 2회이고, 그래도 안 되면 미통과 표시와 함께 출력한다.
8

리포트 조립

build_report코드

모든 결과를 하나의 리포트로 묶는다.

하는 일
중립 요약, 공통 사실, 주요 쟁점, 일부만 다룬 사실, 함께 생각할 질문, 제외된 기사를 정리한다. 검증을 통과하지 못했다면 그 사실을 표시한다.

단독 보도 경로같은 사건 기사가 1건일 때

같은 주제로 판정된 기사가 정확히 1건이고 본문이 있으면, 4~8번(비교 경로) 대신 아래 5개 노드로 갑니다. 비교할 대상이 없기 때문입니다. 본문이 없으면 "비교할 수 없어요" 안내로 끝납니다.

9

팩트체크

single_factcheckLLM 1회

기사 속 핵심 주장을 뽑고 근거와 출처를 점검한다.

하는 일
  • 주장 6~10개를 뽑는다. 핵심 의혹과 당사자 반론·해명을 반드시 포함한다.
  • 주장마다 근거 문장, 출처 유형(공식 자료, 당사자 발언, 익명 관계자, 전문가 발언, 기자 취재 내용, 수치), 교차 확인이 필요한 이유를 적는다.
안전장치
근거 문장이 본문에 글자 그대로 없는 주장은 "본문 근거 없음"으로 표시하고 기사 작성에서 뺀다.
한계
기사 안의 근거와 출처를 점검하는 것이며, 다른 언론의 확인 보도가 없어 외부 교차 확인은 하지 못한다.
10

교차 확인

single_researchLLM 1회검색

다른 언론사의 관련 기사와 배경 자료를 찾아 주장별로 교차 확인한다.

하는 일
  • 9번이 만든 검색어(핵심 사건, 당사자 반론, 관련 제도·경과)로 뉴스를 검색해 다른 언론사 기사 최대 8건의 본문을 가져온다. 같은 언론사 기사는 독립적인 확인이 아니라서 뺀다.
  • 주장마다 교차 확인됨 / 일부 확인 / 확인 불가 / 다른 정보 있음으로 나누고, 판정마다 그 기사에서 가져온 문장(인용)을 붙인다. "틀렸다"는 판정은 하지 않는다.
  • 독자가 알면 좋은 배경과 원 기사와 다른 관점(당사자 반론, 다른 전문가 해석)을 자료에서 3~6개 고른다.
안전장치
인용문이 해당 언론사 기사의 제목이나 본문에 실제로 없으면 그 근거를 인정하지 않는다. 근거가 없는 "교차 확인됨"은 "확인 불가"로 내리고, 근거 없는 배경·관점 항목은 버린다.
한계
외부 자료는 뉴스 검색 결과에 한정된다. 공식 문서·법령·통계 원자료는 직접 확인하지 않는다.
11

기사 새로 작성

write_singleLLM 1회

확인된 주장, 교차 확인 결과, 배경·다른 관점으로 새 요약 기사를 쓴다.

하는 일
  • 제목과 3~4개 문단. 모든 문장에 "○○에 따르면"처럼 출처를 밝히고 단정형으로 쓰지 않는다.
  • 핵심 의혹과 당사자 반론을 모두 담고, 평가·감정 어휘와 새로운 결론을 만들지 않는다.
  • "단독 보도이며 다른 언론의 확인이 없다"는 안내는 LLM이 아니라 코드가 별도로 붙인다. (원문에 없는 말이라 검증이 오판하기 때문)
12

표현·근거 검증

check_singleLLM 2회동시 실행

새 기사가 원문에 근거하는지, 표현이 중립적인지 검사한다.

하는 일
  • 새 기사를 주장 단위로 쪼개 원문에 근거가 있는지 확인한다.
  • 평가·감정 표현, 출처 표기, 원문 왜곡·추가 여부를 채점한다.
  • 통과하지 못하면 12번이 아니라 10번으로 돌아가 다시 쓴다. (최대 2회)
13

리포트 조립

build_single코드

새 기사와 팩트체크 결과를 하나로 묶는다.

보조 노드

노드종류역할
judge_fan코드수집한 기사를 기사별 주제 판정으로 나눠 보내는 분기점. 직접 하는 일은 없다.
no_report코드같은 주제 기사가 2건 미만일 때 "비교할 수 없다"는 안내만 만들고 끝낸다.

처리 시간과 안정성을 위한 구조

LLM 서비스가 간헐적으로 80~100초씩 멈추는 것이 측정되어(정상 호출은 3초 안팎), 아래와 같이 대응합니다. 서비스 상태에 따라 분석 시간은 1~3분 사이에서 크게 달라질 수 있습니다.

대응내용
멈춘 호출 재요청llm.py: 요청 크기에 따라 6~30초 안에 응답이 없으면 같은 요청을 한 번 더 보내 먼저 오는 쪽을 쓴다. 실패하면 최대 3회까지 다시 시도하고, 130초가 넘으면 포기한다.
판정과 분석을 동시에process_article: 기사 1건의 "같은 사건인지 판정"과 "기사별 분석"을 동시에 실행해 LLM 단계 하나를 없앤다. 판정에서 제외된 기사의 분석은 버려진다.
기준 사건 생략주요 사건 카드에서 시작한 분석은 헤드라인을 기준 사건으로 그대로 써서 LLM 호출 하나를 아낀다.
기사 하나의 실패 허용기사 하나의 판정·분석이 끝내 실패하거나 응답을 해석하지 못해도 전체 분석은 계속한다. (그 기사만 제외)
재작성 줄이기검증이 "근거 없는 문장"이나 "틀린 언론사 이름"만 지적한 경우, LLM으로 요약을 다시 쓰지 않고 코드가 그 문장·이름을 빼서 바로 통과시킨다. 고친 내용은 결과 화면에 표시한다. 재작성 1라운드는 요약과 검증을 합쳐 40~60초가 든다.
정확한 재작성 지시검증이 "어느 언론사 표기가 틀렸고 근거가 확인된 언론사는 어디인지"까지 알려 준다. 인용문 비교는 물결표·따옴표·공백 차이를 같은 문장으로 본다.

그래프 밖의 LLM 사용

분석 파이프라인(LangGraph)에 들어 있지 않고 별도로 실행되는 LLM 호출입니다.

이름파일역할
주요 뉴스 카드 요약topic_summary.py카드마다 본문을 읽고 두 문장으로 요약한다. 본문이 없으면 LLM을 쓰지 않고 페이지의 요약문(og:description)을 그대로 보여준다.
카테고리 분류categories.py하루 한 번, 구글 뉴스 여러 섹션의 기사 약 230건을 묶음으로 분류한다. 기사마다 주 분야 1개와, 실제로 걸칠 때만 부 분야 1개를 정한다.

한눈에 보는 표

#노드종류한 줄 역할
1collect_articlesLLM + 도구기사 수집, 기준 사건 정하기
2judge_topicLLM (병렬)같은 사건인지 기사별 판정
3filter_articles코드같은 주제 기사만 남기기
4analyze_articleLLM (병렬)기사별 주장·강조·출처 분석
5compare_articlesLLM + 코드공통 사실, 주요 쟁점 도출
6write_summaryLLM중립 요약 작성
7check_biasLLM 2개 + 코드근거·편향 검증, 통과 못 하면 재작성
8build_report코드리포트 조립

코드 기준: graph.py와 nodes/ 폴더. 화면에 보이는 진행 단계 7개는 이 노드들을 사용자용 이름으로 묶은 것입니다.
