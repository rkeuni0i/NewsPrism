뉴스 프레임 비교 멀티에이전트 기획안 v2

2026-11-10 · 구현하며 바뀐 결정과 확인 결과를 반영한 개정판

개요v1 대비 변경중립의 정의에이전트 그래프 같은 주제 판정사실 검증데이터 수집화면확인 현황리스크다음 단계

1. 개요

같은 사건을 다룬 여러 언론사 기사를 에이전트가 병렬로 분석해 모두가 동의하는 사실과 언론사별 시각 차이를 나눠 보여주는 LangGraph 기반 서비스입니다. 키워드로 검색하거나 주요기사를 눌러 비교 리포트를 봅니다.

하는 것기사 수집, 같은 사건 판정, 언론사별 병렬 분석, 공통 사실·쟁점 비교, 중립 요약, 사실 근거 검증 + 편향 검증 루프
하지 않는 것언론사 정치 성향 라벨링, 기사 진위(외부 사실) 판정, 로그인, 실시간 크롤링 스케줄링, 유료벽 우회
입력 / 출력키워드 1개 또는 주요기사 클릭 → 중립 요약 · ① 공통 사실 · ② 시각 차이 · ③ 읽어볼 질문 · 검증 결과
실행 형태FastAPI + 정적 HTML (작업을 백그라운드로 돌리고 진행 상태를 폴링)

2. v1 대비 바뀐 점

항목v1v2 (현재)이유
기사 수집네이버 검색 APISerpApi (Google News + Naver 뉴스), 키 없으면 RSS네이버 개발자센터 신규 등록 목록에서 '검색'이 빠졌고 NAVER API Hub로 이전된 것으로 보임
같은 사건 판정없음judge_topic 에이전트 추가같은 키워드의 다른 사건·후속 기사가 섞임
편향 검증문장 단위 편향 검사사실 근거 검증 + 루브릭 검사'중립' 정의 명확화, 환각 방지
본문 확보실패 시 요약 폴백품질 3단계 기록 (full/partial/snippet)유료벽 기사가 제목만으로 '프레임' 판정을 받는 문제 확인
화면마지막 날 FastAPI검색 + 주요기사 + 진행 상태 + 검증 표요구사항 반영

3. '중립'의 정의

"모든 입장을 같은 분량으로 쓴다"가 아니라 세 층을 분리합니다. 근거 없는 주장을 같은 비중으로 쓰는 거짓 균형도 하지 않습니다.

① 사실 층검증 가능한 진술만 단정. 수집 기사 과반이 뒷받침할 때만.
✗ 1~2곳만 쓴 내용을 '모두 동의'로 서술
② 쟁점 층갈리는 지점은 출처(언론사) 병기, 어느 쪽이 옳은지 판정하지 않음.
✗ "정부의 일방적 결정"
③ 표현 층평가·감정·낙인 어휘 배제.
✗ "강행", "졸속", "논란"

4. 에이전트 그래프

collect_articles검색 → 언론사 중복 제거(후보 10곳) → 본문 추출 → 기준 사건(anchor) 도출
↓
judge_topic × N 병렬기사별로 '기준 사건과 같은 구체적 사건인가' 판정 → filter_articles가 같은 사건만 남김 (2건 미만이면 중단)
↓
analyze_article × M 병렬주장 / 강조 사실(원문 근거 필수) / 출처 / 어조
↓
compare_articles공통 사실(과반) · 시각 차이 · 일부만 다룬 사실 · 질문
↓
write_summary중립 요약 (세 층 규칙 적용)
↓
check_bias사실 근거 검증(원자적 주장 대조) + 루브릭(어휘 / 출처 병기 / 정보 선택). 미통과 시 지적 사항과 함께 write_summary로 되돌림 (최대 2회)
↓
build_report

병렬 실행 (Send + reducer)재시도 루프

생성과 평가 프롬프트는 분리합니다. 기사가 미리 주어지면(샘플 모드) 수집 노드를 건너뜁니다.

5. 같은 주제 판정 에이전트

실제 실행(키워드 '프랑스 최저임금 인상')에서 후보 10건 중 7건만 같은 사건으로 판정됐고, 칼럼 1건과 후속 파업 기사 2건이 제외됐습니다.

  • 기준: 후보 제목들에서 가장 많은 기사가 다루는 하나의 사건을 anchor로 도출.
  • 판정: anchor와 같은 구체적 사건인지 true/false + 근거 한 문장. 같은 사건의 다른 관점은 통과, 다른 시점의 후속 사건은 제외.
  • 한계: 판정이 엄격해 같은 흐름의 후속 보도가 빠질 수 있음. 사용하며 기준 조정.

6. 사실 검증 방법 (논문 근거)

근거적용
Wei et al., Long-form factuality in LLMs (SAFE) · arXiv 2403.18802요약을 원자적 주장으로 분해해 각각 근거로 검증
Lei & Huang, ACL 2025 · arXiv 2506.12978어휘 편향과 정보 편향을 나눠 평가
Frame In, Frame Out · arXiv 2505.05406요약문 자체의 프레이밍 평가, 평가를 생성과 분리
AutoJourn · arXiv 2607.18983경쟁하는 관점을 하나로 뭉개는 위험 → 출처 병기. 검색 결과의 2차 요약만 확인, 원문 미확인

각 주장을 supported / unsupported / contradicted로 판정하고, 근거 문장이 실제 기사 본문에 없으면 supported로 인정하지 않습니다(코드 검사). 단정형 주장은 과반 언론사가 뒷받침해야 합니다.

한계: 수집한 기사끼리의 대조(폐쇄 세계)입니다. 여러 언론사가 같은 오보를 냈다면 통과합니다. 외부 검색으로 사실을 확인하는 SAFE 원형은 확장 과제입니다.

7. 데이터 수집

소스용도특징
SerpApi google_news검색, 주요기사1회 약 25건(고유 17곳). 주요기사는 묶음 안의 여러 언론사까지 펼침
SerpApi naver (뉴스)검색호출당 10건(고유 8곳), 한국 뉴스 품질 좋음
Google News RSS키 없음/실패 시 대체구글 리다이렉트 링크라 원문 URL 복원 필요
  • 두 검색 결과를 번갈아 섞고 언론사당 1건만 남김(후보 10곳). 본문은 trafilatura로 추출.
  • 본문 품질: 500자 이상 full, 200자 이상 partial, 미만은 snippet(제목+요약). 유료벽은 우회하지 않음. snippet 기사는 '빠뜨림' 주장과 어조 판단에서 제외하고 화면에 '제목·요약만'으로 표시.
  • 응답은 samples/cache/에 저장해 호출 한도 절약 (NEWS_NO_CACHE=1로 무시). 검색 1회 = SerpApi 호출 2번.
  • 리포트에는 본문 전문을 싣지 않고 요약과 원문 링크만 표시.

8. 화면 구성

  • 키워드 검색: 입력창 → 결과 목록 → '이 사건 비교하기'
  • 주요기사: Google News 주요기사 → 클릭하면 제목을 키워드로 분석
  • 진행 상태: 수집 → 주제 판정 → 분석 → 비교 → 요약 → 검증 → 조립 (1~2분)
  • 리포트: 중립 요약, ① 공통 사실(보도 언론사 수), ② 시각 차이, ③ 질문, 비교한 기사 링크·제외 사유, 검증 결과 표

API: GET /api/headlines · GET /api/search?q= · POST /api/jobs · GET /api/jobs/{id}

10. 리스크와 대응

리스크대응
유료벽·본문 추출 실패우회하지 않음. snippet으로 표시, 제목 기준 판단에서만 사용
LLM 환각근거 문장이 본문에 없으면 제외(분석)·미인정(검증)
공통 사실 과대 포함코드에서 과반 미만 사실을 '일부만 다룬 사실'로 이동
검증의 폐쇄 세계 한계화면·문서에 명시, 외부 검색 검증을 확장 과제로
SerpApi 호출 한도·비용파일 캐시, 키 없을 때 RSS 대체, 검색당 호출 수 조정
저작권본문 전문 비노출, 요약과 원문 링크만
처리 시간 1~2분백그라운드 작업 + 단계별 진행 표시
